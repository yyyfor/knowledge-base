# AI Coding for Non Technical Users

非技术人员使用 AI Coding 的关键不是先学会写复杂代码，而是学会把目标、上下文、任务粒度、验收标准和安全边界讲清楚。

## 适用层级

- Level 1 Beginner：理解非技术人员能用 AI Coding 做什么。
- Level 2 Intermediate：掌握任务拆解、截图上下文、Plan 模式和 Skills。
- Level 3 Advanced：建立团队级 AI Coding 规范、安全边界和可复用技能库。

## 一句话总结

AI Coding 对非技术人员的价值，是把想法、文档、数据、原型和重复流程变成可验证的产物。

## 核心结论

AI Coding 不只是工程师写代码的工具，也可以帮助产品、运营、项目经理和业务人员整理文档、生成脚本、制作原型、处理数据和自动化重复任务。非技术人员使用 AI Coding 的关键，是把任务拆小、给足上下文、先看计划、逐步验收。截图、样例、项目说明和验收标准通常比抽象描述更有效。安全上，要避免在生产环境练手、不要粘贴密钥、不要执行看不懂的命令。

## 核心概念

- AI Coding：让 AI 参与代码、脚本、页面、文档、数据处理和自动化的人机协作方式。
- Plan Mode：先让 AI 输出计划和风险，再确认执行。
- CLAUDE.md：项目级上下文，记录项目规则、命令、目录结构和协作习惯。
- Memory：用户级偏好，跨项目生效。
- Skill：把重复任务沉淀成带触发条件、步骤、输出格式和检查清单的能力。
- Screenshot Context：用截图传递 UI、布局、视觉层级和错误状态。
- Small Task Loop：一次只做一个可验收的小任务。

## 为什么重要

很多非技术人员的工作并不是“不会代码所以不能自动化”，而是缺少把问题结构化、把上下文交给 AI、并判断结果是否可用的方法。AI Coding 把执行门槛降低后，真正的能力变成了：定义问题、拆解任务、给上下文、验证结果、沉淀流程。

## 关键点

- 非技术人员可以用 AI Coding 做文档整理、原型、数据清洗、自动化脚本、周报和页面生成。
- 截图比长文字更适合描述 UI 问题、设计参考和错误状态。
- 任务越小，AI 越容易成功；大任务应该拆成多个可验证步骤。
- 对话跑偏时，重启或清理上下文通常比反复纠正更有效。
- Memory 是用户级偏好，CLAUDE.md 是项目级规则。
- Skills 适合沉淀高频重复流程，例如会议整理、上线检查、线上问题排查。
- Skill 的 description 应写触发条件，而不是泛泛介绍功能。
- 一个 Skill 只做一件事，避免把审查、发布、调试混在一起。
- 生产环境、密钥、支付和用户数据都属于高风险边界。

## 基础例子

产品经理要做一个功能原型时，可以先给 AI 一张参考截图、一段需求描述、目标用户、页面字段和验收标准。让 AI 先输出实现计划，再分步骤生成页面、检查布局、补空态和错误态，最后整理成评审材料。

运营同学要整理周会纪要时，可以把原始记录交给 Skill，要求输出结论、待办、负责人、截止时间和待确认事项。缺失信息必须标注待确认，而不是让 AI 猜。

## 实务应用

- 产品经理：PRD 检查、原型生成、竞品页面拆解、评审材料整理。
- 运营：周报、会议纪要、活动复盘、数据整理和自动化脚本。
- 项目经理：项目进展一页纸、风险清单、上线 checklist、跨团队同步材料。
- 业务分析：把网页、报告和新闻整理成结构化知识库条目。
- 个人效率：用 Skills 沉淀自己的固定输出格式和工作流程。

## 典型流程

### 非技术人员 AI Coding 工作流

- 明确目标：我要得到什么产物。
- 给上下文：截图、文件、样例、项目规则、限制条件。
- 先看计划：要求 AI 说明将做什么、会改哪里、有什么风险。
- 小步执行：一次只做一件可验收的事。
- 验收结果：检查内容、格式、交互、错误状态和边界情况。
- 沉淀 Skill：如果任务会重复，就写成固定流程。
- 做安全检查：涉及生产、密钥、个人数据时暂停并确认。

### Skill 设计流程

- 写清触发条件。
- 写清输入材料。
- 写清执行步骤。
- 写清输出格式。
- 写清不能猜测的内容。
- 写清失败时如何标注。
- 限制一个 Skill 只做一类事。

## 可复用框架 / 方法论

### 三类常用 Skills

- 工作流型：把固定步骤打包，例如整理周会、生成日报、整理网页知识。
- 检查清单型：上线前、发版前、提交前逐项检查，例如 PRD 验收、设计一致性、异常状态和测试结果。
- 领域专家型：把判断框架和 SOP 固化，例如线上问题排查、业务分析、竞品研究。

### AI Coding 安全框架

- 先解释再执行：看懂 AI 要做什么。
- 不懂命令先问：不要批准看不懂的命令。
- 生产不练手：先在本地或测试环境验证。
- 密钥不粘贴：API key、token、cookie、数据库密码都不能随意给 AI。
- 重要操作留痕：记录改了什么、为什么改、如何验证。

## 常见误区

- 误区：非技术人员必须先学编程才能用 AI Coding。实际更重要的是结构化表达和验收能力。
- 误区：一次给 AI 一个大需求。大任务容易中途跑偏，应拆成小任务。
- 误区：在跑偏对话里反复纠正。旧上下文会污染后续判断，必要时应重启。
- 误区：Skill 描述写成功能介绍。description 应写触发条件。
- 误区：一个 Skill 包办所有事。Skill 越泛，触发越不准。
- 误区：能跑就安全。生成代码仍需要测试、安全检查和权限审查。

## 风险点

- 误执行命令：非技术人员可能批准自己看不懂的操作。
- 生产事故：直接在生产数据库、线上配置或支付链路练手。
- 密钥泄露：把 API key、cookie、token 或内部数据粘贴给 AI。
- 结果不可验收：目标不清，AI 产物看似完整但无法判断是否正确。
- 工具功能过时：Claude Design、Kami、Claude Code 等能力会变化，需要定期复查。

## 进阶内容

### 截图作为上下文

截图能同时传递布局、颜色、层级、状态和视觉参考。对于 UI 问题，截图通常比文字描述更准确。适合用在页面调整、设计参考、错误复现和移动端适配。

### Memory 与 CLAUDE.md

Memory 记录跨项目偏好，例如语言、回答风格、先看计划再执行。CLAUDE.md 记录项目级规则，例如启动命令、目录结构、测试命令、设计系统和注意事项。两者不能混用。

### 工具化排版与原型

文章提到 Kami 可把内容排成 PDF、一页纸、简历或幻灯片；Claude Design 可基于截图或文档生成原型、落地页或演示材料。工具功能变化快，知识库中应把它们作为案例而不是永久结论。

## 案例

### 案例 1：需求上线检查 Skill

上线前检查 PRD 验收标准、设计稿一致性、空态、报错、超时、埋点和测试环境验证。输出每项 Pass / Fail，有 Fail 必须修完再发布。

### 案例 2：线上问题排查 Skill

收到用户反馈或告警后，先收集截图、日志、影响范围和最近变更。再按现象判断优先检查方向，例如白屏看前端错误和发布记录，接口超时看服务监控和慢查询，数据异常看数据变更和上下游依赖。

### 案例 3：项目进展一页纸

把项目背景、当前进度、风险、下一步和需要决策的问题交给 AI，生成一页纸给老板或评审会。重点不是排版好看，而是信息清晰、风险前置、下一步明确。

## 重要数据 / 案例 / 引用

- 文中把 Skills 分成工作流型、检查清单型和领域专家型。
- Skill 的 description 应写触发条件，这是提升触发准确性的关键。
- Kami、Claude Design 等工具属于产品能力信息，需定期更新。
- 安全建议包括先解释、看懂命令、生产不练手、不要粘贴密钥。

- 行业研究：观察 AI Coding 如何从工程工具变成通用生产力工具。
- 写作素材：可扩展为“非技术人员 AI Coding 入门手册”。
- 培训分享：适合给产品、运营和项目经理做内部培训。
- 后续提问或深度研究：深入研究团队 Skills 库、AI Coding 安全规范和非技术人员验收标准。
