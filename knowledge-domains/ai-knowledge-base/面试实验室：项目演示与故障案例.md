# 面试实验室：项目演示与故障案例

把问答落实为可运行的实验与可核对的证据。本章保留原资料的 Lab 路线和故障案例，所有项目路径均属于独立示例，不是现有小程序功能。

## 项目介绍模板

示例开发者用 Python 和 FastAPI 做了一个学习规模的企业知识与 Agent 平台。文档经过解析、分块，并被索引两次：Elasticsearch 做 BM25，Qdrant 存 embedding。查询经过可选的查询改写、并行的关键词和向量检索、倒数排名融合（RRF）以及本地 LLM 重排序，答案附带编号引用，包含文档版本和来源。外围有治理生命周期、在检索时执行的 ACL、Neo4j GraphRAG、实体消歧，以及分别评估检索和生成的评估服务。

在此之上，我有意把 Agent 做了两遍：第一遍不用框架，包含 schema 校验的动作、预算、人工审批和幂等写入；第二遍用 LangGraph 状态图，只有一个由模型驱动的规划节点，加上确定性校验、带 checkpoint 的审批暂停和执行账本。我在写入后立即杀掉进程，再恢复，用账本证明没有重复写入。知识检索也作为只读 MCP server 暴露。示例开发者用 21 个 golden 和对抗性任务、多次重复来评估 Agent，报告 pass@1、pass^k 以及必须保持为 0 的“未审批写入”指标。

这是资料作者的项目描述模板。没有实际做过的功能不要改成自己的经历，文中的样本数和演示结果也不是本小程序的测试结果。

## 故障案例与演示核对

模型没算就猜了答案。→ required_tools 把 schema 收窄为下一个必需工具。关键步骤要用代码强制。

检索完美（Recall@3 = 1.0），但引用准确率只有 0.5。→ 检索和生成要分开评估。

重复审批。→ 幂等键 + ON CONFLICT DO NOTHING 让第二次审批变成只读。

让模型服务报错的 schema：Ollama 无法把 maxLength 2000 和嵌套可空对象编译成语法。→ 二分排查、扁平化、所有字段设为必填，并加回归测试。

我自己的 prompt 重构把 Agent 弄坏了：“return tool=finish”被改成“finish”，llama3 就一直循环调用 calculate。单元测试全过，是线上评估套件发现的。→ 恢复原措辞，重跑 15/15 通过，并用测试锁定。Prompt 就是代码。

写入后崩溃。→ LangGraph 会重跑未完成的节点；账本检查返回已有回执，而不是再写一次。
