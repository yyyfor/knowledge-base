# 面试实验室：多智能体

本章收录面试实验室的完整问答，保留题号与英文问题。实现细节来自独立的学习示例项目，不代表现有小程序已部署这些功能，也不代表读者已有相关经历；面试回答应替换为自己的真实实践。

## G1 · 什么时候使用多智能体？

英文问题：When would you use multi-agent?

只有当任务能拆成相对独立的专业领域、受益于隔离的上下文、可以并行、并且有清晰的合并规则时才用，比如跨很多来源的广泛调研。先建立“单 Agent + 工具”的基线，比较质量、延迟、成本和可调试性。多智能体系统的 token 消耗通常是单 Agent 的数倍。

## G2 · Handoff 与 agent-as-tool 的区别？

英文问题：Handoff vs agent-as-tool?

Handoff：控制权和对话转交给另一个 Agent，适合所有权真正变化的场景（分诊 → 账单专员）。Agent-as-tool：主 Agent 保持控制，像调用函数一样调用专家并拿回结果，更容易保持统一的策略、用户体验和 trace。

## G3 · 多智能体常见的失败模式？

英文问题：What are common multi-agent failure modes?

Agent 之间丢失上下文、职责重叠、循环委派、意见无法收敛、重复的工具调用、成本成倍放大，以及 trace 中责任不清。解决：明确的拓扑、带类型的消息契约、共享状态只有一个所有者、预算、终止规则和最终裁决者。

## G4 · 你会把 follow-up Agent 做成多智能体吗？

英文问题：Would you make your follow-up agent multi-agent?

不会。它只有三个工具和一条短的线性流程；单 Agent，甚至一个 workflow，更便宜也更容易审计。只有当比如“跨多个文档集合并行调研”显示出可衡量的收益时，我才会重新考虑。Lab 12 §7 有一个用数据比较两者的练习。
