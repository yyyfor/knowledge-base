# 面试实验室：16 周项目学习计划

学习计划包括第 0 周准备和第 1–16 周训练。时间是练习建议，可按基础调整。命令与路径属于原资料的独立示例仓库，需先取得对应项目并核对环境；不会由小程序执行，也不表示这些脚本存在于本小程序仓库。

## 第 0 周 · 环境搭建与前置知识

建议投入：6–10 小时。目标：项目在你的电脑上跑起来，并熟悉所用工具。

够用即可地学习 HTTP/REST、Docker、Git、SQL 和 Python venv/async。

pip install -e '.[dev,graph,agent]'；启动 Postgres、Redis、Elasticsearch、Qdrant。

安装 Ollama，拉取 llama3 和 embeddinggemma。

pytest -q 通过；在浏览器打开 /docs。

验收产物：一页笔记：五个服务分别做什么。

## 第 1 周 · 知识 API（Lab 1）

建议投入：10 小时。目标：理解请求如何流经分层 API。

在 Swagger 中创建、查看、删除文档。

追踪 main.py → api/documents.py → services/knowledge.py → repositories/documents.py。

动手破坏：提交空标题，哪一层拒绝了它？

验收产物：POST /documents 的时序图。

## 第 2 周 · BM25 关键词检索（Lab 2）

建议投入：10 小时。目标：理解词法检索及其盲点。

导入示例数据；GET /search?q=annual leave。

对比 “C-101” 与改写说法；阅读 ES mapping。

动手破坏：搜索文档中没有的同义词。

验收产物：5 个查询的结果表：你的第一个迷你 golden set。

## 第 3 周 · Embedding、分块与向量 RAG（Lab 3）

建议投入：12 小时。目标：建立对 embedding 和基础 RAG 流水线的直觉。

按 labs/lab03_vector_rag.md：上传 PDF、预览分块、建索引、POST /rag/query。

阅读 chunking.py 和 services/rag.py。

动手破坏：同一问题分别用 chunk_size 100 和 3000。

验收产物：分块大小对比及结论。

## 第 4 周 · 混合检索、RRF、重排序、评估（Lab 4）

建议投入：12 小时。目标：所有生产级 RAG 的核心。

POST /rag/hybrid 分别用 bm25 / vector / hybrid，并开关 rerank。

对所有模式运行 eval/run_eval.py。

手算 RRF；停掉 Qdrant，观察优雅降级。

验收产物：指标表，以及“为什么要混合检索”的录音回答。

## 第 5 周 · 本体与知识建模（Lab 5）

建议投入：8 小时。目标：把一堆文本变成业务模型。

阅读 dto/graph.py 中的最小本体。

写 5 个能力问题（competency questions），检查本体能否回答。

增加一个实体类型和一个关系，并说明理由。

验收产物：扩展后的本体图。

## 第 6 周 · 知识图谱与 GraphRAG（Lab 6）

建议投入：10 小时。目标：带可解释路径的多跳问题。

启动 Neo4j；抽取、审阅并写入图。

在两跳问题上比较向量与图。

动手破坏：三跳问题，遍历需要什么限制？

验收产物：一个带证据路径的两跳示例。

## 第 7 周 · 实体消歧、近重复、矛盾检测（Lab 7）

建议投入：8 小时。目标：在不误合并的前提下提炼知识。

按 labs/lab07_entity_resolution.md 在 Swagger 中练习。

阅读 refinement/entity_resolution.py 及其测试。

动手破坏：把 MERGE_THRESHOLD 调到 0.8，找出错误合并。

验收产物：回答：为 1000 万条公司记录设计实体消歧。

## 第 8 周 · 治理、溯源与生命周期（Lab 8）

建议投入：8 小时。目标：只有已批准、有效的知识可被检索，并有完整审计轨迹。

把文档从 draft → validated → approved → published → deprecated。

回滚一个版本。

GOVERNANCE_ENABLED=true：确认未发布的文档不会被检索到。

验收产物：生命周期图，标出每个转换由谁执行。

## 第 9 周 · 评估、可观测性、安全（Lab 9–10）

建议投入：12 小时。目标：衡量质量、看清发生了什么、证明访问控制有效。

带基线的生成评估。

查看 /observability/summary。

开启 SECURITY_ENABLED 并使用两个身份：低权限用户无论通过 RAG 还是 Agent 都取不到受限文档。

验收产物：“质量下降”事故处理手册。

## 第 10 周 · 从零实现 Agent 循环（Lab 11）

建议投入：12 小时。目标：在使用框架前，彻底理解 Agent 是什么。

按 lab11_agent_foundations.md 完成步骤 1–9。

阅读 runtime.py 和 tests/test_agent_runtime.py。

不加 required_tools 运行组合任务 5 次，统计错误答案。

验收产物：凭记忆画出循环；回答“什么是 Agent？”

## 第 11 周 · 工具、记忆、上下文与可靠性

建议投入：10 小时。目标：函数调用、上下文工程、审批过期与崩溃恢复。

阅读 memory.py 及其测试。

可选：拉取支持工具调用的模型，尝试 mode=native_tools。

在运行中杀掉 API，重启后 POST /agent/runs/{id}/resume。

验收产物：用自己的话写出“崩溃点”表格。

## 第 12 周 · 持久化 Agent、MCP 与评估（Lab 12）

建议投入：14 小时。目标：能扛住故障、通过审计、衡量可靠性。

在 Swagger 中跑一遍带审批的 v2 流程。

python scripts/lab12_crash_demo.py → PASS。

运行 MCP server 并连接一个客户端。

用 3 次重复运行 eval/run_agent_suite.py。

验收产物：评估报告 + ADR：单 Agent vs 多 Agent。

## 第 13 周 · LLM 基础与生态

建议投入：10 小时。目标：Transformer、训练、LoRA、推理、缓存、推理模型、框架、协议、Benchmark、安全框架。

每天一个主题（见 08 指南第 13 周表格）。

把“模型与生态”卡片逐一口头作答。

超过 2 分钟的回答重新学习。

验收产物：L 部分所有卡片标记为“已掌握”。

## 第 14 周 · 项目故事与系统设计

建议投入：10 小时。目标：2 分钟讲清项目；在时间压力下做设计。

录制 2 分钟和 5 分钟版本的项目介绍。

两个 40 分钟设计：知识助手、退款 Agent。

每个设计列出 5 个失败模式及检测方法。

验收产物：两份带取舍说明的设计草图。

## 第 15 周 · 模拟面试

建议投入：10 小时。目标：在接近真实的条件下发挥。

3 次模拟：15 分钟项目、25 分钟设计、20 分钟快问快答（随机 + 仅星标）。

现场手写 Agent 循环、RRF、指标、重试。

第二天重做最弱的三个回答。

验收产物：弱项清单，并逐一补强。

## 第 16 周 · 收尾打磨

建议投入：6–8 小时。目标：现场演示一切正常；保持状态。

重新运行所有测试和演示。

过一遍术语表：每个术语 20 秒内讲清。

准备向面试官提的问题；面试前一天休息。

验收产物：准备就绪。
