# 面试实验室：评估与可观测性

本章收录面试实验室的完整问答，保留题号与英文问题。实现细节来自独立的学习示例项目，不代表现有小程序已部署这些功能，也不代表读者已有相关经历；面试回答应替换为自己的真实实践。

## F1 · 如何评估一个 Agent？

英文问题：How do you evaluate an agent?

评估轨迹，而不只是最终答案。指标：任务成功；工具选择正确；参数正确；状态转换合法；没有未授权或重复的副作用；证据完整；步骤效率；延迟；成本。通过未经批准的写入得到的正确答案算失败。示例项目的评估套件检查工具轨迹、关键答案，以及重复审批或拒绝不会产生额外写入。

## F2 · 模型结果不确定，这如何改变评估？

英文问题：Models are non-deterministic. How does that change evaluation?

每个任务运行 N 次并报告比率。pass@k：k 次中至少一次成功，适合探索。pass^k（来自 τ-bench）：k 次全部成功，衡量可靠性，对生产更重要。尽量固定种子或 temperature，用置信区间比较，不要相信单次演示。

## F3 · LLM-as-judge 有哪些风险？

英文问题：What are the risks of LLM-as-judge?

模型评审可能存在位置、长度与同家族偏好，且受提示与版本影响。用人工标注校准、固定版本、明确量表和成对交换顺序比较。引用 ID 与文本是否存在适合程序检查，但“引用是否支持论断”需要额外语义标准，不能把文本匹配当成完整的正确性验证。

## F4 · 如何构建 golden set 和对抗集？

英文问题：How do you build golden and adversarial sets?

Golden set 来自真实使用日志和领域专家，覆盖常见、长尾、标识符、时间、权限、歧义和多跳场景。对抗集包括：被注入的文档、超出用户权限的请求、工具超时、互相矛盾的来源，以及正确行为是拒绝或升级的“不可能任务”。每次生产事故都加成新的回归用例。

## F5 · 修改 prompt 或模型时如何防止退化？

英文问题：How do you stop regressions when you change a prompt or model?

给 prompt、模型、工具和索引固定版本。在 CI 中运行 golden 和对抗套件，与保存的基线比较，指标下降超过阈值就阻止发布。然后在生产中 canary 或 shadow。示例项目的评估服务拒绝与使用不同数据集、K 或 judge 设置的基线比较，避免拿苹果比橘子。

## F6 · Agent 需要追踪哪些内容？

英文问题：What do you trace for an agent?

每个 run：trace ID；模型、prompt 和工具版本；每一步的动作；参数的脱敏摘要；结果或错误；重试；审批事件；每个 span 的延迟；输入输出 token；成本；最终状态。不要记录密钥或原始敏感文本；示例项目的 runtime 失败时只记录异常类型。常用工具：OpenTelemetry（有 GenAI 语义约定）、Langfuse、LangSmith、Arize Phoenix。

## F7 · 线上会监控什么？

英文问题：What would you monitor online?

任务成功率（显式反馈 + 代理指标）、升级和审批率、拒绝率、工具错误率、超时和预算触发、每个任务的步数、P95 延迟、每个任务的 token 和成本、策略违规，以及注入检测命中。还有检索健康度：无结果率、新鲜度延迟。
