# Agent 工作流与可靠恢复

Agent 在受控工具与停止条件内根据中间结果选择下一步。固定工作流（Workflow）由代码决定步骤，智能体控制流包含模型决策。选择依据是任务是否需要动态探索，不是框架是否热门。

## 入门：从固定流程到有限循环

固定流程适合“读取文档 → 抽取 → 校验 → 人工确认”。ReAct（Reasoning and Acting，推理与行动结合）依据工具观察继续选择动作；Planner-Executor（规划器与执行器）先形成计划再执行。模型自我批评可以帮助发现问题，但不是独立验证。

多智能体把任务拆成不同角色，还会增加消息、权限和协调成本。先用单流程做基线；只有分工确实提高质量或并行效率时再增加角色。每次运行规定最大步骤、总时长、费用与重复调用限制，超出后返回明确停止原因。

## 进阶：工具是接口契约

每个工具定义名称、用途、输入 Schema、输出、权限、超时和副作用。服务端校验参数、认证身份和资源权限。只读工具与写工具分开；写操作展示确切参数供用户确认，批准记录绑定参数哈希与有效期，参数变化后重新批准。

MCP（Model Context Protocol，模型上下文协议）统一工具与资源的连接方式；直接调用和 MCP 调用可以复用业务逻辑，但都不能省略授权、错误处理和幂等。工具返回的文本属于数据，不能反过来改变宿主的安全规则。

## 项目实践：暂停后继续的行动草稿

练习只开放读取公开知识和形成行动草稿。状态保存 runId、任务版本、当前节点、证据引用、已完成工具结果和审批状态。审批前暂停，恢复后重新核对证据及权限，再保存用户确认的行动。该方案尚未在本小程序上线，也不会自动上传私人行动。

Checkpoint（检查点）保存可以继续执行的状态。它不保证外部副作用只执行一次：发送请求成功后、保存检查点前进程崩溃，恢复时可能重发。写工具应使用稳定业务幂等键，并保存执行收据；结果未知时查询业务系统核对，而不是盲目重试。

## 高阶：可靠性与审计

可以使用事务发件箱提交业务意图，由工作者执行；如果外部系统不支持幂等，就必须设计查证、去重或人工处理路径。不要把“恢复到节点”称为端到端 exactly-once（恰好一次执行）。审批和回滚也要考虑外部操作是否可逆。

记录结构化动作、参数摘要、证据版本、执行结果、耗时和停止原因，不依赖或要求公开模型内部推理过程。测试超时、取消、重启、权限撤销、重复工具结果和用户拒绝批准，确认状态最终一致且不会重复创建记录。
