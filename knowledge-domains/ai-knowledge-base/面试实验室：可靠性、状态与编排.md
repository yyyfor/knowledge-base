# 面试实验室：可靠性、状态与编排

本章收录面试实验室的完整问答，保留题号与英文问题。实现细节来自独立的学习示例项目，不代表现有小程序已部署这些功能，也不代表读者已有相关经历；面试回答应替换为自己的真实实践。

## E1 · 如何防止重复的副作用？

英文问题：How do you prevent duplicate side effects?

给每个意图中的动作一个幂等键。执行前持久化意图，执行后持久化回执，并在存储层或提供方去重。恢复时查账本，而不是问模型发生了什么。示例项目的实现：key = sha256(run_id + 校验后的参数)，配合 Postgres 唯一约束和 ON CONFLICT DO NOTHING；重复审批返回已有记录。对外部 API，如果对方支持，就把这个 key 传过去。

## E2 · Runtime 什么时候应该重试工具？

英文问题：When should the runtime retry a tool?

先给错误分类。瞬时故障（超时、429、503）用带抖动的有界指数退避重试。校验或业务错误不重试：把错误反馈给模型，或者直接失败。非幂等的写入只有在有幂等键、或确认第一次没有落地时才重试。示例项目的 runtime 只重试只读的 search，最多一次。

## E3 · 工具成功了，但 Agent 崩溃了或以为失败了，怎么办？

英文问题：The tool succeeded, but the agent crashed or thinks it failed. What now?

外部操作成功、账本尚未保存时崩溃，属于结果未知，不能仅因为查不到回执就安全重做。优先使用外部服务支持的幂等键或状态查询进行核对。示例项目把内部写入和唯一业务键放在同一数据库事务中，重复审批返回已有记录；这能保护该内部写入，不等于所有外部 API 都拥有相同保证。事务发件箱负责可靠投递意图，消费方仍需处理重复。

## E4 · 什么是 checkpoint？里面应该有什么？

英文问题：What is a checkpoint, and what goes into one?

每一步之后的持久快照：run ID、当前节点或步骤、输入、观察、带幂等键的待处理动作、回执、已用预算，以及模型、prompt 和工具的版本。它支持为审批而暂停、崩溃后恢复，以及“时间旅行”调试。LangGraph 为此提供 checkpointer，Temporal 这类持久化执行在工作流层面做到这一点。给 state schema 加版本，旧的 checkpoint 才能迁移。

## E5 · 什么是补偿（saga）？

英文问题：What is compensation (saga)?

当某个效果无法回滚（邮件已发出、钱已付出）时，执行一个补偿动作：发送更正、退款。提前为每个写工具设计好它的补偿动作，并把两者都记录下来。

## E6 · 设计人工审批环节。

英文问题：Design the human-approval step

按风险决定，而不是按模型的置信度。给审批人看：确切的动作和参数、证据和引用、影响、请求人以及过期时间。批准的必须正是所展示的内容；如果审批人修改了，就重新校验并生成新的 key。记录审批人、时间和决定。拒绝是安全的终态。等待审批的时间不应消耗 run 的超时（示例项目的实现不计入）。示例项目的实现现在支持审批过期、委托审批和四眼原则（AGENT_FOUR_EYES）。

## E7 · 如何让你的 runtime 不再一次只能跑一个 Agent？

英文问题：How would you scale your runtime beyond one agent at a time?

去掉全局锁。把 run 放进队列，由无状态 worker 领取。用按 run 的锁或乐观并发（带 compare-and-swap 的 version 列），保证两个 worker 不会推进同一个 run。所有状态保存在 Postgres。加上按租户的配额和限流，以及处理“毒 run”的死信队列。

## E8 · 如何控制 Agent 的成本？

英文问题：How do you control agent cost?

每个 run 的 token、成本和步数预算；模型分层（小模型做路由，大模型做难题）；稳定前缀以利用 prompt caching；截断工具输出；压缩历史；缓存检索和查询改写；答案已知时提前结束（示例项目的系统提示会推动模型在事实齐全后立即 finish）。关注每个成功任务的成本，而不只是每次调用的成本。
